# TrpgMaps —— Win7 / 32 位兼容版

用 **.NET Framework + WinForms + GDI+** 重写的 DM 端，目标是把运行门槛压到最低：
免安装、绿色部署，解压即用，能在 Windows 7 SP1 32 位老机器上跑。

玩家端完全不区分版本 —— 依然是手机浏览器打开的网页，两版共用同一套页面与 HTTP 接口。

> **本文件是"这个版本怎么用 / 怎么改"的说明书。**
> 想换一台电脑继续开发，先看根目录的 **`开发须知.md`**（工具链、构建、无头测试、已知陷阱、
> 迁移检查清单）；想看每轮改了什么、为什么，看根目录的 **`版本说明.md` 第五节**。

## 1. 快速开始

### 方式一：双击（推荐）

双击 **`编译并运行.bat`** —— 自动编译，然后启动程序。
以后只想启动、不想再编译，双击 **`运行程序.bat`**。

### 方式二：命令行

```bat
cd win7版本
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
bin\Release\TrpgMaps.exe
```

### 方式三：Visual Studio

直接打开 `TrpgMaps.csproj`（经典 .NET Framework 工程格式，VS2010 以后都能打开）按 F5。

> 需要**编译**的机器装 Visual Studio 2022；**运行**的机器什么都不用装（见下一节）。

> ### ⚠️ 手机扫了码却打不开玩家页面？
>
> 先看这一条，**十有八九是这个**：Windows 防火墙里有一条"阻止"本程序接收局域网连接的规则。
> 双击 **`放行防火墙.bat`** 即可修复（弹一次管理员确认），或直接用界面里网络面板的
> **「放行防火墙」** 按钮。原理、成因和排查方法见 **第 13 节**。
>
> 顺带说明为什么容易被误判：这个故障下 **DM 端一切正常** —— 服务起来了、地址对、二维码能扫、
> 所有自测全通过，只有手机连不上。因为自测走的是 `127.0.0.1`，而**防火墙不过滤回环流量**。

## 2. 目标框架：只有 v3.5（一个 exe 通吃）

**本版只编一个目标框架，就是 .NET Framework 3.5。**

```bat
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
:: 输出 bin\Release\TrpgMaps.exe
```

早期这里还提供过一版 v4.0 目标，后来**砍掉了**。原因很简单：**v3.5 严格覆盖 v4.0 的所有机器，反过来不成立**。

| | **v3.5**（保留） | v4.0（已删除） |
|---|---|---|
| Win7 是否需要装东西 | **不用装**（系统自带、默认启用的 3.5.1） | **要装** .NET Framework 4.0+ |
| Win8 / 8.1 / 10 / 11 | **不用装**（自动退回系统自带的 CLR 4.x，见下） | 不用装 |
| 适用机器集合 | Win7 SP1 → Win11（超集） | Win8 → Win11（子集，把 Win7 排除在外） |
| 分发形态 | 一个目录，零安装 | 一个目录，零安装 |

也就是说：**留 v4.0 的唯一效果，是让"老机器用户需要先装一次运行时"。** 对一个主打"傻瓜式发过去双击就能用"的工具来说，
这是纯粹的负担，没有任何补偿。所以现在源码、工程文件、脚本里都只认 v3.5。

### 为什么 v3.5 反而是"万能包"

v3.5 目标编出来的 exe 旁边会多一个 **`TrpgMaps.exe.config`**，里面写了两条运行时回退：

```xml
<startup useLegacyV2RuntimeActivationPolicy="true">
  <supportedRuntime version="v2.0.50727" />   <!-- Win7 / Vista 自带的 CLR 2.0 -->
  <supportedRuntime version="v4.0" />          <!-- 新系统自带的 CLR 4.x -->
</startup>
```

- 在 **Win7** 上：用系统自带、默认启用的 .NET 3.5.1 → **零安装**。
- 在 **Win8 / 8.1 / 10 / 11** 上：这些系统默认**不**启用 .NET 3.5，CLR 2.0 根本不存在，
  于是自动落到系统自带的 CLR 4.x 上跑同一份 IL。

之所以能这样"降级回退"，是因为代码刻意只用 .NET 2.0 就已经存在的 API
（没有 `async/await`、没有 `Task`、没有 `String.IsNullOrWhiteSpace`、没有三参数的 `Path.Combine`、
没有 `Tuple` / `ISet` / `HasFlag`）。这份 IL 在 CLR 2.0 和 CLR 4.x 上都能跑。

> **已实测**：在一台只装了 .NET 4.x、`.NET 3.5` 功能未启用的 Windows 10 上，
> `bin\Release\TrpgMaps.exe` 可以直接双击运行（起服务、抓界面截图都正常）。

**怎么编：** 直接跑 `scripts\build.ps1`（或双击 `编译并运行.bat`），没有框架开关可挑。
不需要本机装 Targeting Pack —— 工程引用了 `Microsoft.NETFramework.ReferenceAssemblies`，
它只在**编译期**提供 v3.5 的参考程序集，产物里不会有任何第三方 DLL。

### 打包分发

**要给别人用，跑一条命令就行**（安装包 / 便携包 / 升级包 / 源码 zip 一次全出）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\make_release.ps1
```

详细说明见第 14 节。如果只是想把程序拷到别的机器上跑，**把 `bin\Release\` 整个目录拷走即可**：

```
TrpgMaps.exe          ← 程序本体，约 540 KB（含内嵌的 7 档图标）
TrpgMaps.exe.config   ← 运行时回退配置（务必一起拷走）
TrpgMaps.pdb          ← 调试符号，分发时可以删掉
Resources\appicon.ico ← 窗口图标（exe 自己的图标已内嵌；这个文件是运行期回退用，丢了不影响启动）
Resources\avatar.png  ← 「关于」面板的头像（丢了只是不显示头像）
maps\                       ← 底图（可自行增删）
terrain\ entity\ item\      ← 地形 / 实体 / 物品素材（可自行增删）
wwwroot\                    ← 玩家端网页
放行防火墙.bat              ← 可选，手机连不上时的双击修复入口（见第 13 节）
```

**没有任何第三方 DLL。** 体积分两部分看：

| | 大小 |
|---|---|
| **程序本体**（exe + config + wwwroot + 图标 + 头像） | **约 0.9 MB** |
| 自带素材数据（`maps\` ≈ 2.7 MB + `terrain\` ≈ 31 MB） | 约 34 MB |

> 那张「自带的示例底图」是 19 张 1672×941 的图（早期是 PNG、合计 50 MB；
> 现在换成内置解码器支持的有损 WebP，只要 2.7 MB，见「底图格式」一节），
> 地形素材 14 张 1254×1254 才是体积大头 —— 这些是**你自己的资源**，
> 换掉/删掉目录立刻瘦下来，跟程序本身没关系。本文档里说"程序本体很小"指的都是前一行那个 0.9 MB。

> ⚠️ **必须**把 `TrpgMaps.exe.config` 一起拷走。
> 少了它，exe 只认 CLR 2.0，在没有启用 .NET 3.5 的新系统上会提示"需要 .NET Framework 3.5"而打不开 ——
> 这正是最初"v3.5 版本打不开"的原因。

## 3. 界面与操作

启动后全屏无边框，就是一个 DM 专用地图屏。左侧竖排按钮，**最下面那颗是独立贴底的**：

| 按钮 | 作用 | 有没有灰色遮罩 |
|---|---|---|
| 展开 | 把侧栏从 60px 展开到 180px，显示按钮文字 | — |
| 地图设置 | 从左侧滑出浮空面板：网格尺度、底图缩放方式、**底图旋转**、**撤掉地图**、网格颜色、底图列表、导入图片 | **有** |
| 网络 | 从左侧滑出浮空面板：监听 IP / 端口、防火墙状态、玩家二维码、在线名册、房间锁定 | **有** |
| 绘图 | 地图**右上角**的浮窗（地形 / 实体 / 物品），可拖动 | **没有**（见下） |
| 全屏 | 全屏 / 窗口化切换 | — |
| 关于 | 从左侧滑出浮空面板（和「地图设置 / 网络」同一套）：作者头像、版本号、作者主页、源码仓库、检查更新 | **有** |

> 「关于」**不参与从顶往下的排布**，而是从侧栏底边往上数（`SidebarPanel.BottomSlots`），
> 所以它在窗口左下方贴底，和上面那一列之间空着一大截。以后再加功能按钮也不会把它挤走。
> 它和绘图面板同样互斥（开它会把绘图浮窗关掉）。

#### 面板之间是互斥的

- **「地图设置」「网络」「关于」**：从左侧滑出，紧贴侧栏（中间留 **2px**），
  地图上盖一层半透明灰色遮罩；**点遮罩空白处 = 关面板 + 收回侧栏**。
  这三个面板和展开的侧栏是**并存**的（展开态下按钮有文字，方便认）。
  它们走的是同一套 `OpenPanel` / `CloseAll` / `BuildPanelContent`，
  新增一个面板只需要在 `PanelKind` 里加一项、在 `BuildPanelContent` 里加一个分支。
- **「绘图」**：停在**屏幕右上角**，**不套遮罩** —— 它存在的意义就是让你一边开着一边在地图上画
  （有遮罩的话鼠标点不到地图）。所以它开着的时候**地图照常接收鼠标**，空白处点击也不关面板。

打开「绘图」时会先**清场**：关掉除自己以外的全部浮空面板、撤掉灰色遮罩，再把侧栏收回 60px。
这条统一收在 `ClearPanelsForDrawing()` 里，**新增面板时不需要各自重复实现**。
反过来，打开「地图设置 / 网络 / 关于」时也会先把绘图面板关掉（`OpenPanel` 开头那两行）——
两个方向都要管，不然屏幕上会同时挂着两个面板。

> 为什么绘图面板也走这一步：它和另外几个面板**互斥**。几个面板同时开着时，遮罩的层级关系
> 会变得没法解释（无遮罩面板在遮罩上面还是下面？点遮罩算不算点地图？），
> 所以干脆规定"**同一时刻只有一个面板**"。

**网络面板里有两行专门给"手机连不上"准备的**（详见第 13 节）：

| 行 | 说明 |
|---|---|
| `防火墙：…` | 绿=已放行；红=**被阻止，手机连不上**；灰=未放行（首次连接会弹系统授权框） |
| 「放行防火墙（需管理员确认）」 | 点一下弹 UAC，自动删掉阻止规则、补上入站放行，**不用去翻防火墙控制台** |

这一行不是装饰：手机连不上时地址和二维码其实**都是对的**，光看界面根本看不出问题。

- 点地图空白处 = 关闭面板 + 收回侧栏。
- 面板打开时地图上会盖一层半透明灰色遮罩，突出面板。
- 侧栏与浮空面板之间只留 **2px** 缝隙，收起和展开两种状态下都是 2px。
- 侧栏内**五个**按钮的左右内缩**随侧栏宽度插值**：收起（60px）时内缩 3px，
  展开（180px）时内缩 14px。所以展开后按钮不再"顶满"侧栏两侧，图标和文字都往右让出一段，
  视觉上更透气；图标位置在动画全程保持不动（内缩量增加的部分正好等于按钮左移量）。

### 撤掉地图（回到"只有网格"的初始状态）

地图面板里有一个红色危险色的 **「撤掉地图」** 按钮，作用是把当前底图卸掉，
让画面回到**程序刚打开时那样：没有底图，只有网格**。

| 行为 | 说明 |
|---|---|
| 撤掉的是什么 | **只是"当前选中"这一项**（`MapStore.ClearCurrent()`），`maps\` 里的文件**一个都不删** |
| 其它状态 | 缩放方式 / 旋转角 / 网格颜色 / 网格尺度**全部不动** —— 桌子摆好之后方向就定了，撤张图不该顺带把这些也重置 |
| 幂等 | 本来就没有底图时点它，返回 `{"success":false,"message":"本来就没有底图"}`，**不报错、不弹框**，当无事发生 |
| 广播 | 撤掉后立刻发一条 `map_change`，其中 `image` / `url` **都是空字符串**，且四格锚点**全部为 0**（见第 3.2 节） |
| 重新装上 | 在底图列表里点一张就又回来了，无需重新上传 |

> **为什么载荷里的空底图要显式写 0 锚点**：手机拿到的是"没有底图"这个事实，
> 如果这时还下发上一次的锚点，手机就会按旧底图的中心去摆一个**不存在的**网格。
> 所以"没有底图 ⇒ 锚点为 0"是在**构造载荷的地方**判定的，不是去读画布 ——
> 画布在没有底图时算出来的"锚点"会退化成"底图铺满视口"，那是个**假值**。

命令行等价入口：`POST /api/maps/remove`（仅本机）。

### 底图旋转（顺时针 90° / 180°）

地图面板里有「顺时针 90°」和「旋转 180°」两个按钮，右边显示当前角度：

| 按钮 | 行为 |
|---|---|
| 顺时针 90° | 每次 +90°，**可连点**：0→90→180→270→0 |
| 旋转 180° | 每次 +180°：0↔180、90↔270 |

**转的只是底图，网格不跟着转。** 网格是桌面上的实体战斗网格 —— 屏幕转了它也不该转，
否则"进度条写 2.5cm/格、拿尺子量 2.5cm"这件事就说不清了。自检里专门有一条断言盯着这个
（四个角度下格子像素数都必须还是 `cm × 37.8`）。

旋转角是**全局显示状态**（存在 `MapStore` 里，不跟着单张底图走）：桌子摆好之后方向就定了，
换底图时不该再转回来。

实现上不是"把图片拧过去硬裁"：转 90/270 时先算一个**转置过的逻辑视口**（宽高互换），
在逻辑坐标系里用同一套拉伸/填充规则把底图摆好，最后整体旋转贴到屏幕上。
所以旋转后的底图仍然遵守"拉伸（铺满）/ 填充（保持比例）"的语义，不会转完露黑边或被切掉一半。

### 网格颜色：只有纯白 / 纯黑，跟着底图自动切

网格线**只有两种颜色**——纯白 `rgba(255,255,255,0.78)` 或纯黑 `rgba(0,0,0,0.78)`，
不存在灰线或半透明渐变。0.78 的透明度是刻意选的：线要"看着是纯色"，但又不能把底图盖死。

地图面板里有「网格颜色」下拉，三档：

| 选项 | 行为 |
|---|---|
| 自动（跟随底图） | **默认**。服务端按底图平均亮度决定：`均值 ≥ 0.5 → 黑线`，否则白线 |
| 白色 | 强制白线 |
| 黑色 | 强制黑线 |

下拉框下面还有一行**说明文字**（例如 `自动 → 白线（底图平均亮度 0.34，偏暗）`），
把"为什么是白线"写清楚——这样某张图被判错了，你一眼能看出来是亮度算偏了，
而不是对着一个没有反馈的下拉框猜。没有底图时按白线（无底图背景是深色）。

**为什么是"整张图一个判断"而不是"逐像素自适应"**：逐像素会让同一根网格线在明暗交界处
一段黑一段白，变成斑马线，格子就断了。网格是拿来在桌上量距离的，**连续性比局部对比度重要**，
所以只在整幅图上做一次判断，边缘情况用上面的手动开关兜底。

判定算法：把底图降采样到 **32×32**（1024 个采样点），按 Rec.601 权重
（`0.299R + 0.587G + 0.114B`）求整幅的平均亮度。透明像素先按 `Theme.Background`（#1A1A1A）合成再算，
不然带 alpha 的 PNG 会被当成纯黑。阈值固定在 0.5。

判定结果**按文件缓存**（key = 路径 + 文件长度 + `LastWriteTimeUtc`），同一张图只分析一次；
改了图（长度或时间变了）会自动重算。

**颜色由服务端算好再下发**，`map_change` / `request_map` 的负载里带
`gridColor`（已解析成 `white`/`black`）和 `gridMode`（`auto`/`white`/`black`）。
手机端不做任何判断，拿到什么画什么 —— 手机上解一张 3MB 的图纯属浪费，
而且万一手机和电脑判断不一致，玩家屏上的网格会和 DM 屏上不一样。

> **本机这 19 张底图的实测**（`--selfcheck` 会打这张表，按亮度从高到低排）：
> 合计 **白线 17 张 / 黑线 2 张**。19 张 AI 生成的 PNG 里只有 **2 张判黑线**
> —— `荒漠.png`（0.68）和 `寺院.png`（0.67），其余 17 张都是白线。
> 亮度范围 0.10（`密道走廊.png`）～ 0.68，阈值 0.5 落在中间，判定是单调的；
> 但 `石砖地.png`(0.50)、`海岸.png`(0.49)、`地砖.png`(0.48)、`泥土地.png`(0.48)、
> `草地.png`(0.47)、`水域.png`(0.47) 这 **6 张离阈值很近**，自检里会标 `[贴阈值,可手动改]`
> —— 这几张就是最值得用面板手动指定颜色的候选。

### 手机端：在电脑的角度上**再**顺时针转 90°

约定**手机屏幕的"上端"对应电脑屏幕的"左端"、"下端"对应"右端"**，也就是：

```
手机看到的画面 = 电脑看到的画面 顺时针转 90°（网格关系 +90°，底图 = 电脑角度 +90°）
```

所以手机上显示的旋转角是 `电脑设定角度 + 90°`，随 `map_change` 里的 `rotation` 字段下发。
实现细节（都在 `wwwroot/js/player.js`）：

- 内容盒子按**旋转前**的尺寸摆（转 90/270 时宽高互换），转过去才正好铺满屏幕；
  一直用 `100vw×100vh` 的话转 90° 之后内容比屏幕"高"，上下会被切掉一截。
- 网格画布按 `offsetWidth/offsetHeight`（**布局**尺寸）取大小，不能用
  `getBoundingClientRect()` —— 后者会把旋转后的包围盒给你，宽高是互换的，
  网格会被拉成横竖不一样长的格子。
- 手指拖动的位移要**换算进已经旋转过的容器坐标系**，否则画面转了 90° 之后
  手指往右拖、地图会往上下跑。

### 坐标绑定：电脑上画在哪，手机上就画在哪

这是两版之间**唯一一处必须逐像素对齐**的东西。之前手机上画出来的东西位置总是偏的，
根因是**两端各算各的**：电脑端以"屏幕左上角"为网格原点，手机端以"自己那块画布的左上角"为原点，
两边画布尺寸、底图缩放比例都不一样，于是同一个格子落在两个不同的地方。

现在改成**以底图中心为唯一共享参照**。

#### 为什么是"底图中心"

电脑端有两条性质：

1. 底图**永远居中**摆放在画布上（`ComputeImageRect` 把图摆在 `(W-w)/2, (H-h)/2`）；
2. 旋转是**绕画布中心**转的。

两条合起来 ⇒ **底图中心 ≡ 画布中心，且旋转前后都是**。
底图又是**两端唯一真实共有的东西**（手机也能拿到同一张图），所以它就是天然的锚点。
换成"画布左上角"就不成立了：两端的画布尺寸根本不同，左上角对不上。

#### 契约：4 个与分辨率无关的数

每次 `map_change` / `api/request_map` 都带这 4 个数（在 `Core/GridAnchor.cs` 里定义）：

| 字段 | 含义 | 用哪个视口算 |
|---|---|---|
| `gridCellsX` | 底图在当前适配模式下**横向占多少格** | **逻辑**视口（转 90/270 时宽高互换） |
| `gridCellsY` | 底图**纵向占多少格** | 逻辑视口 |
| `gridHalfW` | 画布**半宽**是多少格 | **屏幕**视口（**不互换**） |
| `gridHalfH` | 画布**半高**是多少格 | 屏幕视口 |

> ⚠️ **前两个和"逻辑视口"、后两个和"屏幕视口"绑定，写反是最容易犯的错。**
> 底图是在逻辑坐标系里摆的（所以格数要按逻辑宽高算），
> 而"画布多大"是要换算到**屏幕像素偏移**上用的（所以不能换）。
> 自检里 `CheckGridAnchor` 专门断言这一条：转象限时 `cellsX/cellsY` 必须**互换**，
> 而 `halfW/halfH` **必须不变**。

四格数**全部 `readonly`，只发布不修改** —— 用一个新实例整体替换引用
（`MapCanvas.AnchorSnapshot`）。原因：这个值**在 UI 线程重算、在 HTTP 线程读**，
如果原地改字段，HTTP 线程可能读到"改了一半"的中间态。

#### 电脑端怎么算

```csharp
var cell = CellPixels;                      // cm/格 * 37.8，与底图无关
var rect = ComputeImageRect();              // 底图在逻辑视口里的摆放矩形
_anchor = new GridAnchor(rect.Width  / cell, rect.Height / cell,   // 底图占几格
                         Width  / (2.0 * cell), Height / (2.0 * cell)); // 画布半宽半高几格
```

没有底图、或格子太小（`cell <= 0.5`）、或控件还没布局（`Width/Height <= 0`）时，
直接发布 **`(0,0,0,0)`** —— 明确的"这个锚点不可用"，不要发一个能算出答案但没意义的数。

#### 手机端怎么还原

手机不做任何"猜"，严格按公式重算（`wwwroot/js/player.js` 的 `computeGridFrame()`）：

```
origin = 底图中心
旋转   = -mapRotation                 // 电脑的网格是"屏幕轴对齐 + 画布锚定"的，
                                      // 在底图坐标系里看就等于转了 -rotation
cellW  = 底图宽度 / gridCellsX        // 横向一格多少 CSS 像素
cellH  = 底图高度 / gridCellsY        // 纵向一格多少 CSS 像素
ox     = -gridHalfW * cellW           // 电脑屏幕原点相对底图中心的偏移
oy     = -gridHalfH * cellH
格 (x,y) 的落点 = origin + R(-rotation) * (ox + x*cellW, oy + y*cellH)
```

注意 `cellW` / `cellH` 是**分开的**：底图可能非等比缩放，两端每格像素数本来就不一样，
但"**格 (x,y) 落在底图上的相对位置**"是同一个比率 —— 这才是真正要保证的东西。

#### 靠什么保证它不会悄悄坏掉

`smoke_test.ps1` + `--selfcheck` 里共 4 类断言：

1. **规格层**（`SelfCheck.CheckGridAnchor`，离屏，不开窗口）：在一张 1200×800 的画布上放
   500×320 的探针底图、2.5cm/格，对 `fill`/`contain` × `0/90/180/270` 八种组合
   **独立重算**一遍 4 个格数（不复用被测代码），断言 `cellsX/cellsY` 在四分之一转时互换、
   `halfW/halfH` 不互换。**八种组合偏差实测全为 0**。
2. **传输层**（同一函数）：用 C# 重新实现一遍上面的手机公式，拿 `(0,0) (4,3) (12,6) (-2,-1)`
   四个探针，比较"某格落在底图上的比率（0..1）"在电脑端和手机端是否一致，容差 `0.002`。
   这条是**端到端**的：公式抄错、象限搞反、`ox/oy` 漏一项都会被抓出来。
3. **线上层**（smoke）：断言 SSE 的 `map_change` 里真的带这 4 个字段，且
   `cellsX/cellsY` 的比值**等于底图的宽高比**（`anchor follows the basemap aspect`）。
4. **防串味层**（smoke，最有价值的一条）：把窗口尺寸当未知量消掉。令 `A = 2*halfW`、
   `B = 2*halfH`、`r = 底图宽/高`，在 `fill` 模式下必须满足
   `cellsX == max(A, B*r)` 且 `cellsY == max(A/r, B)`。
   **如果画布上显示的底图是错的、或者干脆没有底图，这条会失败**（那时 `A == cellsX`）——
   换底图时画布没跟着更新这个 bug 就是被它抓出来的。

> **两个自测里揪出来的老 bug**（都不是锚点本身的问题，是"锚点把旧 bug 暴露了"）：
>
> 1. **画布会落后于 `MapStore`。** `POST /api/maps/set` 只改 `MapStore` 然后广播，
>    它没有途径去动 UI —— 于是通过 HTTP 换底图时，电脑画布**还停在上一次那张图上**。
>    锚点是**从画布量出来的**，画布停住了，锚点自然也就停住了。
>    修法：`MainForm.SyncCanvasWithStore()` 每 200ms 比对
>    「名字 / 适配模式 / 旋转角」三元组，不一致就重新同步画布。
> 2. **广播总在重绘之前。** 所有调用点都是"先广播 `map_change`、再刷新自己的画布"，
>    于是**第一条载荷带的是上一张底图的锚点**。修法：算完之后再补一次
>    **600ms 去抖**的纠正广播（`ScheduleAnchorBroadcast()`），保证最终态一定发得出去。

#### 网格大小只对电脑重要

按需求：**电脑上量尺子要准**（格子像素恒等于 `cm/格 × 37.8`，第 3 节的公式里没有底图缩放因子），
**手机上只要"看起来位置几乎完全相同"就行**。所以：

- 电脑端：网格**严格**按 `cm × 37.8` 铺满屏幕，格子是正方形；
- 手机端：格子的**像素尺寸跟着底图走**（`cellW`/`cellH` 分开算，可能不是正方形），
  但每个格子**落在底图上的相对位置**与电脑端一致 ——
  也就是"手机上看起来，格线压在同一条桌布花纹上"。

这也是为什么锚点里传的是**格数**而不是**像素数**：像素数是各端自己的事，格数才是共享语义。

### 控件外观：全部自绘，甩掉系统主题

WinForms 的默认控件在 Win7 和 Win10/11 上长得**完全不一样**（Win7 是 Aero 渐变 + 白色边框，
新系统是平面灰），用默认控件等于把"这是个老程序"直接写在脸上。所以下拉框、输入框、列表、
滑块、按钮**全部改成自绘**，集中在 `Widgets.cs`：

| 控件 | 做法 |
|---|---|
| `ModernDropDown` | 6px 圆角深色填充 + 1px 描边 + 右侧自绘箭头；**没有白色边框，也没有系统那个凸起的下拉按钮**。弹出菜单是独立的无边框圆角窗口，点别处自动收起，支持键盘上下 + 回车 |
| `ModernTextBox` | 内部塞一个无边框 `TextBox`，外面套圆角底；没焦点时描边暗，聚焦时描边变亮 |
| `ModernList` | 行完全自绘（底图列表带缩略图、名册带在线/离线圆点），自带一条细滚动条 |
| `ModernSlider` | 圆角轨道 + 蓝色已填充段 + 圆形滑块 |
| `ModernButton` | 6px 圆角、`FlatStyle.Flat`、无边框；悬停/按下的颜色由基色自动算出来（不用再准备三套图） |

字体统一 **微软雅黑**，开 ClearType。注意 `Ui.Font()` 返回的是**共享缓存实例**，
所以全项目都不能对返回值用 `using` —— 之前就是因为 `using` 把缓存字体 Dispose 掉，
触发过 `Graphics.DrawString` 抛"参数无效"。

### 滚动：横向永远没有，纵向只有一条 4px 短线

① **横向滚动条在结构上就不存在**。面板 `AutoScroll = false`，自己写的 `ScrollViewport`
根本不画横向条；内容比面板宽就直接裁掉。

② **保证内容不可能比面板宽**。每一行都包进一个 `AutoSize` 的 `FlowLayoutPanel`，
并且 `MaximumSize` 卡死在面板内容宽度上，所以任何一行都超不出去。这也是"端口"这种
104px 的窄控件能和整行宽的控件混在同一个纵向列表里的原因。

③ **纵向：装得下就完全不显示滚动条**，装不下才画**一条 4px 的圆角短线**。
短线画在专门留出的槽里、和内容左右都不重叠，**没有箭头、没有轨道底色、没有上下端小方块**，
只在小短线自己滑过的区间内有颜色。鼠标移上去或拖动时变亮。

```csharp
BarWidth  = 4;    // 短线宽度
BarInset  = 4;    // 离面板边缘的内缩，保证不压内容
MinThumb  = 28;   // 内容再长，滑块也至少 28px，不然点不到
WheelStep = 64;   // 一格滚轮 64px
```

④ **滚轮转发**。WinForms 的 `WM_MOUSEWHEEL` 只发给**有焦点**的控件，所以鼠标停在
输入框/下拉框上滚的时候，消息是进输入框的，面板不动 —— 这是最反直觉的一点。
代码里 `HookWheel()` 递归给所有子控件挂了转发（**跳过 `ModernList`**，因为它自己要滚），
现在鼠标在面板任何位置都能滚。

> **但"跳过"还不够 —— 必须显式"吃掉"这个滚轮事件。** 最初只做到"不给 `ModernList`
> 挂转发的 `HookWheel`"，结果鼠标停在**绘图面板的素材列表**上滚动时，
> **列表和整个面板内容会一起滚**：列表滚到底（或顶）之后，WinForms 会把这个
> `WM_MOUSEWHEEL` **冒泡给父容器**，父容器（`ScrollViewport`）于是也跟着滚。
>
> 修法是 `Widgets.cs` 里的 `WheelRouter`：一个 **30ms 的 `Environment.TickCount` 时间戳**。
> 列表在 `OnMouseWheel` 里做三件事 —— 滚自己、`WheelRouter.Mark()`、把
> `HandledMouseEventArgs.Handled` 置 `true`。任何转发逻辑在动手之前先问一句
> `WheelRouter.TakenRecently`，**最近 30ms 内被列表消费过就不再处理**。
>
> 为什么不只靠 `Handled`：`Handled` 只在 `ScrollableControl` 认这条消息时才是权威的，
> 自绘控件走的是自己那条路；而且父容器的滚动有时是**通过 `OnMouseWheel` 之外**
> 的路径触发的。加一个时间戳是"同一个滚轮事件只允许生效一次"的兜底，
> 不依赖任何一方的实现细节。

> `ModernSlider` 刻意**不**重写 `OnMouseWheel`：鼠标停在滑块上滚，应该是滚面板，而不是偷偷改网格尺度。

> 一句话总结这三条滚轮规则：**鼠标停在素材列表上 ⇒ 只有列表滚；
> 鼠标停在面板别处 ⇒ 只有面板滚；两者永远不会同时滚。**

窗口最小尺寸是 **800×480**（不是 600）。放到 480 是为了照顾 1280×720 的老网本：
内容装不下没关系，面板自己会纵向滚。

`--ui` 的模式：`base`｜`sidebar`｜`map`｜`mapcollapsed`｜`grid35`｜`closeall`｜`gridreopen`｜`net`｜`about`｜`rotate90`｜`gridcolor`｜`draw`｜`drawbrush`｜`drawcone`｜`drawbrushloose`｜`drawtangent`｜`all`。
- `grid35` = 把网格滑块拉到 3.5cm；`closeall` = 关闭全部面板后再截一张；
  `gridreopen` = **先设成 3.5cm、关闭面板、重新打开**，用来验证滑块复位 bug 有没有复发；
  `about` = 展开侧栏 + 打开「关于」面板（头像 / 版本 / 作者链接 / 更新状态）。
  它前面会先 `CloseDrawPanel()`：关于面板和绘图面板是互斥的，不关掉的话右上角浮窗会一起入镜；
  `rotate90` = 把底图顺时针转 90° 再截（看旋转按钮和当前角度显示）；
  `gridcolor` = 网格颜色设成「自动」、选中列表里第一张底图、打开地图面板再截
  （看下拉框和那行说明文字）；
  `draw` = 绘图面板（右上角浮窗）打开、选中第一张地形素材；
  `drawbrush` = 笔刷模式摆好原点正在量半径（看半透明红覆盖格、**半透明蓝的实际形状**、
  候选点、距离读数）；半径 2 格、选区方式「严格」→ 红 13 格；
  `drawcone` = 同上但形状换成扇形 —— 蓝层换成一段扇形，这是"实际形状"这一层最直观的一张（红 5 格）；
  `drawbrushloose` = 和 `drawbrush` **同一套原点/半径/形状**，只把选区方式切到「宽泛」——
  两张对着看就能确认红色确实把蓝圆压到的格都算上了（13 格 → 21 格）；
  `drawtangent` = **半径定死 1.5 格（7.5 尺）+ 宽泛**：圆正好和上下左右四条格线相切，
  切线外那一圈按新规则**不算**被扫到（红 9 格，和严格一样）—— 这是"相切算不算"的判据现场；
- `all` = 在**同一个进程里**依次截全部 15 张（`01-base` … `15-about`），
  这样无人值守时只需启动一次程序，尽量少触发"是否允许运行"这类系统弹窗。
  `draw` / `drawbrush` / `drawcone` / `drawbrushloose` / `drawtangent` 前面会先 `CloseAll`，
  否则上一步留下的「地图设置」面板会挡住左半边地图，选区一半在面板底下。
  > 每加一个画面就往 `all` 的序列里加一条，**不要**新开一次启动：
  > 无人值守时"启动次数"才是最贵的资源。
  > ⚠️ `all` 的**顺序**有讲究：`drawbrushloose` 和 `drawtangent` 排在最后，因为它们会把
  > 选区方式切成「宽泛」，而前面几张（`drawbrush` / `drawcone`）要的是默认的「严格」；
  > `about` 又排在它们之后，因为它会把绘图面板关掉。

> **截图是"屏幕实拍"，所以真实鼠标会污染画面。**
> `--ui` 要把窗口真的显示出来，于是系统会把**当前鼠标位置**当成一次 `WM_MOUSEMOVE`
> 灌进来；脚本刚摆好的"原点 + 2 格半径"会被鼠标所在的位置覆盖，
> 截出来的圆有多大纯看鼠标停在哪儿（实测变成半径 9 半格、读数写着 22.5 尺）。
> 现在 `SetupShotBrush()` 摆完画面就置上 `DrawPanel.ShotLocked`，
> 鼠标驱动的预览刷新全部短路；真实使用时这个锁永远是关的。
> 调试这类"画面和日志对不上"的问题时，`SetupShotBrushVisible()` 会往 `app.log`
> 写一行 `截图画笔：… 左界=… 右界=… → 原点格=(…) 目标格=(…) 半径=N 格`，
> 把"为什么选中这几格"的中间值全列出来 —— 先看这一行，再怀疑别的地方。

| 源文件 | `图标.png`（根目录），由 `scripts\make_icon.py` 写盘 |
| 产物 | `Resources\appicon.ico`，**7 档尺寸**：16 / 24 / 32 / 48 / 64 / 128 / 256，共 277 644 B |
| 工程引用 | `<ApplicationIcon>Resources\appicon.ico</ApplicationIcon>` |
| 运行时读取 | exe 同级 `Resources\appicon.ico`（`CopyToOutputDirectory=PreserveNewest`） |

**为什么 16–128 用经典 DIB、256 用 PNG**：`.ico` 允许 256×256 那一档用 PNG 压缩，
其余档位用未压缩的 DIB。全用 DIB 会让 ico 涨到 2MB 以上，全用 PNG 则老系统
（Win7 的某些路径）读不出小尺寸档。**混合是最稳的：小的兼容优先，大的省空间。**

**图标回退链**（`MainForm.ApplyAppIcon()`）：先试 256 档 → 再试 48 → 再试 32 →
最后从 exe 自身资源里 `ExtractAssociatedIcon` 兜底。这样即使 `Resources\` 目录被删掉，
窗口图标也不会变成空白方块（那是"程序崩了"的视觉信号，很误导）。

> `scripts\make_icon.py` 是**开发期辅助脚本**，只在需要重新生成图标时手动跑一次；
> 生成的 `Resources\appicon.ico` 已经进工程，日常编译不会重新生成它
> （也就不需要在编译机上装 Python + Pillow）。

### 关于界面文字里的 emoji

界面文字里**刻意不用任何 emoji**（`🗺️`、`✅`、`🔓` 这一类）。
原因：本版走 GDI（`TextRenderer`）绘制文字，Windows 7 的字体回退链里没有 emoji 字体，
这些字符会渲染成"豆腐块"（空心方框）。需要图形的地方一律用 PNG 贴图（侧栏那五个按钮图标）。

`●`（U+25CF）是例外，它属于 WGL4 字符集，Windows 各版本的系统字体都有，所以"● 在线 / ● 离线"可以放心用。

### 地图渲染

- **默认不加载任何底图，只显示网格**；网格恒定可见，默认 **2.5cm / 格**。
- 标称比例沿用原版：**37.8 像素 = 1 厘米**，所以 2.5cm 的格子约 94.5 像素。
- **网格尺度与底图完全无关（重要）**：格子像素边长恒等于 `cm/格 × 37.8`，
  从屏幕左上角起算、铺满整个视口；底图用 `fill`（铺满，可能裁切）或 `contain`
  （完整显示，留黑边）**只影响底图自己怎么摆**，不会带着网格一起缩放。
  > 早期版本把网格乘上了底图的适配比例，导致"没底图时量着准、装上 3840×2160 大图后
  > 格子缩到标称值的一半甚至更小"。现在这条公式里已经没有底图缩放因子了。
- 缩放级别滑块范围 **0.5–10 cm/格**，拖动即时生效；关闭面板再打开，滑块**保持原值**
  （值存在主窗口上，不随面板销毁而重置）。
- 网格线颜色只有纯白 / 纯黑两种，默认按底图亮度自动选（见上「网格颜色」一节）。
- 底图用 `Graphics.DrawImage` 贴到画布上时套了一层 `ImageAttributes` 并设
  `WrapMode.TileFlipXY`：默认的插值在采样越出源图边界时会当成"透明黑"，
  于是在**填充模式**下那条贴边的底图边缘会出现 1–3px 的暗缝。`TileFlipXY` 把边界外的采样
  改成镜像边缘像素，暗缝就没了（这个 bug 是给网格颜色做像素级自检时才暴露出来的）。

### 底图格式：PNG/JPG 走 GDI+，WebP 走自研 VP8 解码

`maps\` 里放什么格式都行，程序按**文件头**分派（`Core/ImageLoader.cs`）：

| 格式 | 谁解 |
|---|---|
| PNG / JPG / JPEG / BMP / GIF / TIFF | 系统自带的 **GDI+**（`Image.FromStream`） |
| **WebP** | **程序内置的纯托管 VP8 解码器**（`Core/Vp8Decoder.cs` + `Core/Vp8Tables.cs`） |

#### 为什么 WebP 得自己写

**GDI+ / System.Drawing 从 Win7 到 Win11 都不支持 WebP。** Windows 的 WebP 解码器在 WIC 里，
是 **Win10 1809** 才加进去的，Win7 完全没有。所以 `Image.FromStream` 对任何 `.webp` 一律抛异常 ——
底图列表里看得见，画出来却是**全黑**（预览和「地图设置」里的缩略图一起黑）。

能不能退一步引个库？不能：本项目最大的卖点就是「**没有任何第三方 DLL**」（见第 6 节的目录结构，
exe + config + wwwroot 就这些）。引 `libwebp.dll` 会把这个优点直接抹掉，所以**自己实现**。

解码器严格按 **RFC 6386** 写：RIFF/WEBP 容器 → VP8 关键帧帧头 → 布尔算术解码器 →
分段 / 环路滤波 / 量化 / 参考帧 / 熵头 → 令牌分区 → 逐行重建（含 4×4 与 16×16 预测模式、WHT、IDCT）→
环路滤波 → YUV→BGRA。**只支持 lossy `VP8 ` 关键帧**（本项目的底图全是这种）。

#### 两个必须记住的坑

1. **`ImageSizeReader` 也要认这个格式。**
   程序里量底图尺寸走的是"**只读文件头、不整张解码**"那条路（`Core/Models.cs`）。
   加新格式时如果只改了 `ImageLoader`，图能画出来，但**尺寸量错** ——
   而 `GridAnchor` 的格数和 `ComputeImageRect()` 都建立在"底图多少像素"上，
   于是"**网格与底图位置绑定**"会**静默失效**（画面对得上、手机对不上，比黑图难发现得多）。
   WebP 这里就踩过：`"VP8 "` 分支原先读到的是**同步码**，把 1672×941 报成 **298×2054**。
   > 加格式的规矩：**`ImageLoader` 和 `ImageSizeReader` 必须一起改。**

2. **VP8 的 YUV 是 BT.601 有限范围（studio swing），解码端要先展开回全范围。**
   亮度 Y ∈ [16,235]、色度 U/V ∈ [16,240]，编码端存进去的是 `Y = 16 + (219/255)·Y_full`。
   必须做 `(Y-16)·255/219`、`(U/V-128)·255/224` 之后再做 BT.601 矩阵。
   少了这一步，画面**结构完全正确**、只是**对比度只剩 86%**（发灰发白）——最不容易被发现的一类错。

#### 怎么确认它解得对

- **逐像素对拍**：同一张 `.webp` 分别用本程序解、用 Pillow(libwebp) 解，逐像素求平均绝对误差。
  19 张真实底图 **0.68 ~ 2.07（平均 1.52）**，合成图更严（0.00 ~ 0.01）→ 与 GDI+ 解 PNG 等价。
- **网格颜色判定必须一致**：同一张底图的 PNG 与 WebP 版本，`auto` 模式给出的线色**逐张相同**。
- **离屏自检有 WebP 段**（9.4 节）：19 张全部断言"解码尺寸 == 只读文件头量到的尺寸"、
  "亮度标准差 / 亮度级数够多（不是一片糊）"，并导出 `_webp_decode.png` 供目视。
- **耗时**：平均 **163 ms/张**（19 张合计 3106 ms）—— 色度上采样用的是**最近邻**（`x>>1`）而非
  libwebp 的 fancy 上采样（那点差别只在高频彩色边缘才看得出，实测误差 < 2），
  因为**老机器的解码时间是硬约束**。

#### 想只用 WebP 分发？注意构建会把源码里的 PNG 拷回来

`TrpgMaps.csproj` 里是这么写的：

```xml
<Content Include="maps\**\*">
  <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
</Content>
```

也就是说**每次编译都会把源码 `maps\` 下的所有文件拷进 `bin\Release\maps`**
（`PreserveNewest` 只是跳过更新的，不会删旧的）。所以：

- 只把 webp 塞进 `bin\Release\maps`、源码 `maps\` 里还留着 PNG 的话，
  **下次一编译，那 19 张 PNG 又回来了**，输出目录从 2.7 MB 涨回 50 MB。
- 想彻底走 webp，**源码 `maps\` 里也该只放 webp**（开发与分发同一份，最省心）；
  或者嫌源码仓里不想放二进制，就在编译后手动清一遍输出目录里的 `.png`。

体积对照（本机实测）：19 张 1672×941 的 PNG 合计 **50 MB**；换成有损 WebP
后合计 **2.7 MB**。这就是当初要换格式的原因，也是为什么值得为它写一个解码器。

### 绘图面板（地形 / 实体 / 物品）

侧栏第 4 个按钮（画笔图标）打开绘图面板。**这是本软件最重的一个面板**。

**窗口行为**

- 停在屏幕**右上角**的浮窗，**不套灰色遮罩**（`OpenPanel` 那套遮罩会吃掉地图点击，
  而这个面板存在的意义就是让你一边开着一遍在地图上画）。
- 可拖动（拖标题栏），圆角矩形，**尺寸固定 334×560**，内容超出时纵向滚动。
- 点标题栏的 `×` 或再点一次侧栏「绘图」按钮关闭。
- 面板开着的时候**地图照常接收鼠标**：画布把原始鼠标事件转给面板，空白处点击不再关闭面板。

**三个分类 · 两层图层**

| 分类 | 目录 | 一格能叠几层 | 图层位置 |
|---|---|---|---|
| 地形 terrain | `terrain\` | **一层**，新地形覆盖旧地形 | 最下层（0） |
| 实体 entity | `entity\` | **不限层数**，按落笔顺序叠 | 与物品同级（1） |
| 物品 item | `item\` | **一层**，新物品覆盖旧物品 | 与物品同级（1） |

渲染顺序由**服务端**排好（地形在前，实体/物品按插入序在后），手机端照着数组顺序铺图，
自己不做任何遮挡判断 —— 这样电脑和手机看到的画面永远一致。
分类按钮已预留齐全，目前只有 `terrain\` 里有素材，另两个目录会自动建出来留空。

**手动 / 笔刷两种模式**（打开面板默认「手动」）

- **手动**：按住左键在地图上拖动，鼠标扫过的格子逐个铺上当前选中的素材。
  一次「按下→拖动→松开」对同一个格子**只写一次**（`HashSet` 去重），
  否则手抖会让实体在一格里叠出十几层。
- **笔刷**：先点一下放**原点**，屏幕上随即在横向/纵向标出候选落点；
  鼠标移到另一个点时会显示与原点的距离，**点第二下**把距离定下来当半径，按形状成图。

**落点吸附与距离**：所有吸附都在**半格**的整数栅格上做 ——
格子中心 = (奇,奇)，边中点 / 网格线交点 = 某个坐标是偶数。这样
"格心 / 线中点 / 交点"三种落点用一套整数坐标就能统一表达，
距离换算也不会积累浮点误差：**1 格 = 5 尺，1 个半格 = 2.5 尺**。

**四种笔刷形状**：线形（任意角度）、锥形/扇形、立方、球形/圆形。
形状选完之后有两种**选区方式**（面板上的「严格 / 宽泛」开关，见下节）：

| 形状 | 严格判定（格心在形状内） |
|---|---|
| 立方 | `|dx| ≤ r` 且 `|dy| ≤ r` |
| 球形/圆形 | `dx² + dy² ≤ r²` |
| 锥形/扇形 | 球形 ∩ 与朝向的夹角 ≤ 半张角 |
| 线形 | 沿线段按 1/4 格步长采样去重（supercover 近似） |

扇形在半径定下来之后还能跟着鼠标**绕原点转**，第三下点击固定角度。

**选区方式：严格 / 宽泛**（第十轮新增，第十一轮修正「相切不算」）

同一个形状落到格子上可以有两种口径，面板上「画笔模式」下面一行就是开关：

| 方式 | 判定 | 结果 |
|---|---|---|
| **严格**（默认） | **格心**落在形状里才算 | 桌面战棋的通行做法，边界没有争议；半径 2 格时是 13 格 |
| **宽泛** | 形状**真正压到**这个格才算（格矩形与形状的重叠面积 **> 0**） | 贴合"目测形状边线压到哪几格"；半径 2 格时是 21 格 |

- 两种方式**共用同一个形状定义**：切换只改"形状怎么落到格上"，**蓝色实际形状层完全不动** ——
  红色最多，蓝色永远一样。
- ⚠️ **宽泛里"只相切"不算**（用户反馈后修正）：形状边线正好压在格线上、或只从格角蹭过去时，
  那一格整格都在形状外面，一像素都没盖到。半格坐标下格边界、圆心、半径全是整数，
  所以圆的相切能**精确**判出来（距离 == 半径就不算）；扇形则靠"把格矩形内缩一个极小量
  `LooseEps` 再做点/射线判据"剔除零面积接触 —— 内缩量必须**大于**点判据的角度容差，
  否则会被容差吃掉（90° 张角的两条边界射线正好是 ±45°，最爱压着格角走，就是这个坑）。
- **立方在半径取整数格（且原点在格心）时两种方式结果完全相同**；
  **线形也完全相同**（它本来就是"线段扫过哪些格"）。真正有差别的是圆和扇形 ——
  但**半径取 1.5 格时圆和立方又会相同**：形状边线正好压在格线上，外面那一圈只相切。
- 「格心判定」是硬边界、不含糊；宽泛是**故意偏多**的口径（它要回答的是"这一片算不算进范围"，
  而不是"格心在不在里面"）。自检里对这两种口径的格数逐个断言
  （球形 r=4：13/21、球形 r=3（相切）：9/9、立方 r=4：25/25、立方 r=3（相切）：9/9、
  锥形 90°：5/7，且宽泛不向后溢出），并断言「宽泛 ⊇ 严格」。
- 切换选区方式**不会清掉正在摆的选区**（原点 / 半径 / 朝向都还在），
  所以可以一边量半径一边对比两边的格数。

**工具栏右边三个按钮：橡皮擦 / 清空本类 / 清空全部**

| 按钮 | 作用 | 粒度 |
|---|---|---|
| 橡皮擦 | 把笔刷（或手动拖动）扫到的格子上的**当前分类**内容擦掉 | 一格 |
| **清空本类** | 只摘掉**当前选中的那一张素材**画上去的格子 | 一张素材 |
| 清空全部 | 清空地图上全部绘图内容 | 全部 |

- 「清空本类」的**名字**是用户指定的，**行为**是"只摘当前这一张素材"：
  `terrain\` 里同时铺了「高草丛」和「火焰」时，它只摘点名的那一张，另一张一格不动
  （`DrawingStore.ClearAsset`，第十轮）。
  以前这里是按分类清的（`ClearKind`），而一个分类里通常铺了好几种素材，
  点一下就把整类全清了 —— 和「清空全部」看不出区别，等于没有这个按钮。
- 没选中素材时按钮**是灰的**，点了也什么都不会发生。
- 状态行会实时显示「本素材已画 N 格」，点之前就能知道会摘掉多少。
- 三个按钮都**不碰**底图 / 旋转 / 网格颜色 / 网格尺度，也不删 `terrain\`、`entity\`、`item\` 里的图片文件。

**选区提示永远画在最上层**：它不进底图那份离屏缓存，而是每次 `OnPaint` 现画 ——
选区随鼠标每动一下就变，把 3MB 的底图重新合成一遍会卡。主画布因此分成两层：
`_scene`（底图 + 网格 + **已经落笔的内容**）和每帧叠加在上面的选区预览。

### 笔刷预览有两层：红色是"格"，蓝色是"形状"

笔刷模式下（放好原点之后）预览同时画两层，**从下到上**：

| 层 | 画什么 | 回答的问题 |
|---|---|---|
| **红色半透明 + 深红描边** | 覆盖到的**格子**（一格一个方块） | "会被刷上哪些格" |
| **蓝色半透明 + 亮蓝描边** | 形状**本身**：真圆 / 扇形 / 正方 / 线段 | "真正的范围到哪" |
| 候选落点 / 原点标记 / 距离读数 | 交互标记 | 量距离、确认落点 |

为什么要两层：上面的判定是"**格心在不在形状里**"，所以红块拼出来的边界**是阶梯状的**。
半径 2.5 格时，圆边上"格心刚好在圆外、但格子被圆切掉一角"的格子不会被选中，
光看红色会以为圆比实际小。两层叠着看，多出来的部分正好互相补足：

- **红多出来的角** = "这格会被刷上，但圆其实够不到这个角"；
- **蓝多出来的楔形** = "圆真的伸到了这里，但这格的格心在圆外，所以不计入"；
- **紫（红+蓝重叠）** = "两者一致，这一段就是会刷上的范围"。

实现上有两个刻意的选择：

- **蓝色填充的 alpha（62）比红色（70）还低。** 两层半透明叠加时，蓝的 alpha 一大，
  重叠区就会偏向蓝色、把红色盖掉（需求明确要求"红色保持不变"）。所以填充只负责铺一片淡蓝，
  **真正勾形状靠的是近乎不透明的 2.5px 描边** —— 这也是"勾勒出实际形状"的字面做法。
- **画在红色之上、交互标记之下。** 用户要求"在红色半透明选区层上方"；但原点标记、
  候选落点、距离读数是拿来做判断的，被染色就不好用了，所以压在最上面。

`DrawShapeOutline()` 里只有一处单位换算要小心：`RadiusHalf` 的单位是**半格**，
半径像素 = `RadiusHalf × cellPixels / 2`（不是 `× cellPixels`）——
这跟 `DrawGeometry.ToPixel()` 是同一个约定，算错一个系数蓝圆就和红格差半格。
角度也共用一套约定：`Direction` 来自 `Math.Atan2(dy, dx)`（y 轴朝下），
GDI+ 的 `AddArc` 也是"从 +x 轴出发、屏幕上顺时针为正"，可以直接相加，不用翻符号。
另外**张角 360° 要当成整圆处理**，不要"画整圆再补两条半径"——那样中间会多一条从圆心到边界的线。

关闭面板会清掉全部选区状态（原点、半径、朝向），但**已经画好的地形/实体/物品保留**。

**素材与属性**：`terrain\` / `entity\` / `item\` 三个目录，每个目录可配一个
`<分类>_properties.json`（本版是 `terrain\terrain_properties.json`），
每项可写 `name / disadvantageous / cover / obstacle / climb / damage / opacity / note`。
**没写进 JSON 的图片也会照样出现在列表里**（属性全是默认 false、opacity=1），
所以往目录里丢一张图就能直接用，不必先改 JSON。

**不透明度**在生成贴图时就用 `ColorMatrix` **烘进位图**，之后画一格只是一次位块传送。
素材原图 1254×1254、单张 1.3–3.3MB，手机一格才三四十 CSS 像素，
所以手机端走 `/api/terrain/tile/…?px=64` 拿缩好的瓦片，流量从几十兆降到几十 KB。

**落盘**：改动后 900ms（手停下来）写 `drawing.json`，同时只广播一个
`drawingVersion`，内容由手机自己来拉。

### 关于 / 署名面板（侧栏最底部）

侧栏最下面那颗是「关于」，和「地图设置 / 网络」**走同一套浮空面板逻辑**
（左侧抽屉 + 灰色遮罩 + 侧栏缩回，见 `OpenPanel` / `CloseAll` / `ClearPanelsForDrawing`）；
只有绘图面板是例外（它没有遮罩、浮在右上角）。面板内容见 `MainForm.BuildAboutPanel()`：

- **圆形头像**：`Resources\avatar.png`（256×256，构建时复制到 exe 同级）。
  圆形不是画出来的，而是给 `PictureBox` 设一个椭圆 `Region` —— GDI+ 里
  "让控件本身是圆的"比"画一层蒙版"省事，也不用管 `SizeMode` 缩放后的边缘对不齐。
  放在 `Resources\` 而不是 `wwwroot\`：`wwwroot` 会被内置服务器当静态文件发出去，
  头像跟玩家端网页没关系，没必要暴露在局域网上。
- **版本号**：唯一出处是 `Core\AppInfo.cs` 的 `AppInfo.Version`。
  `Properties\AssemblyInfo.cs` 里那份是给资源管理器看的，**两处要一起改**。
- **作者与链接**：`AppInfo.Author` / `GitHubHome` / `GiteeHome` / `GitHubRepo`。
  可点，点了走 `ShellExecute` 打开系统默认浏览器。
- **当前是安装版还是便携版**：`AppRegistry.IsInstalledAt(AppEnv.Root)`。
- **「检查更新」按钮**与启动后自动检查（见下）。

侧栏底部这颗按钮**不参与从顶往下的排布**，而是从底边往上数
（`SidebarPanel.BottomSlots` + `ButtonRect`）。这样以后再加功能按钮也不会把它挤走。
它贴没贴底件事靠着数字断言保证，不靠看截图 —— 非 100% DPI 下截图的右下角本来就会被裁
（见第 9.2 节），"在最边上"的东西恰恰是截图最容易骗人的地方：
`SelfCheck` 会打印 `底部按钮贴底、且不与上方按钮重叠（底边距 12 / 间隙 >= 12）-> OK`。

### 更新检测（Gitee 优先，GitHub 兜底）

实现在 `Core\UpdateCheck.cs`，界面在关于面板。

**为什么不用 Gitee / GitHub 的 release 接口**：两家字段不一样、动不动要 token 或限流，
而"仓库里放一个小 json"两边都能放、都是纯 HTTPS GET，一份实现就够。文件名是
`AppInfo.ManifestFile`（`version.json`），放在仓库的 **`AppInfo.RepoDir`** 目录里 ——
发布出去是 `win32/version.json`（本地目录叫 `win7版本`，上传 git 的源码包里改叫 `win32`，
两边名字不一样，见 14.8）：

```json
{ "version": "1.0.0", "notes": "...", "update": "TrpgMaps_v1.0.0_win32_update.zip",
  "portable": "...", "installer": "...", "mandatory": false }
```

拉取顺序：Gitee 的 `raw/master/win32/` → `raw/main/win32/` → `raw/master/`（旧布局兜底），
全挂了再换 GitHub 的 `raw.githubusercontent.com` 同样三连。**任意一个成功就停**。
`version` 比本机高（`CompareVersions` 按段比数字，后缀忽略）且不等于"不再提示"过的版本，
就弹窗，三个按钮：**更新 / 下次一定 / 不再提示**。

- 「不再提示」把版本号写进 `HKCU\SOFTWARE\TrpgMaps\Update\SkippedVersion`。
  放 HKCU 是因为写 HKLM 要管理员，而"别再提醒我"是用户随手点的动作。
- 「更新」→ 从 releases 下载升级包 → 解到临时目录 → 交给升级程序 → **本程序退出**。

几个刻意的取舍：

- **HTTPS 证书校验是开着的**（没有 `ServerCertificateValidationCallback` 放行）。
  因为最终要下载并**执行**升级包里的程序，关掉校验等于给中间人开后门。
  代价是老 Win7 没打过根证书更新时可能连不上 —— 那个装一次 Windows Update 里的
  根证书更新即可，`Readme.md` 里写了。
- **`.NET 3.5` 的默认协议是 Ssl3|Tls1.0**，而两家站点早就只认 TLS1.2。
  所以 `ConfigureTls()` 用枚举的**数值** 3072 把它或进去
  （3.5 里没有 `Tls12` 这个名字）；老系统没有 TLS1.2 时 schannel 会自己忽略，不会更糟。
- **启动后延迟 4 秒**才查。启动那一瞬间要起 HTTP 服务、查防火墙、渲染底图，
  再塞个网络请求进去会明显拖慢冷启动。
- **`--ui` / `--selfcheck` / `--no-prompts` 一律不联网**（`StartStartupUpdateCheck` 直接返回）。
  自动化场景不该有网络副作用，更不该弹窗。
- 命令行可以单独验：`TrpgMaps.exe --check-update`，退出码 0=有新版本 / 1=已最新 / 2=失败，
  结果写进 `app.log`。

## 4. 玩家名与令牌规则

（与 MAUI 版 / 原 Python 版完全一致）

- 玩家第一次进来自报名字，服务端发一个 32 位十六进制令牌，存在玩家浏览器的 cookie 里。
- 同名再次进入必须带对令牌，否则返回 `TOKEN_MISMATCH`，避免有人冒名顶替。
- 令牌只存在服务端内存里，**程序一重启名册就清空**，属于预期行为。
- 被踢下线的玩家会**保留在名册里标记为离线**，带原令牌仍可重进。

### "在线"到底怎么算（以及为什么必须重新登录）

服务端把"这名玩家在线"这句话，**绑在当前的 SSE 连接 ID 上**：

| 时机 | 服务端动作 |
|---|---|
| 登录成功 | `ConnectionId = 本次连接的 ID`，`Online = true` |
| SSE 流结束（手机息屏 / 浏览器切后台 / 网络断） | 该 ID 对应的玩家 `Online = false` → DM 面板圆点变灰 |
| 玩家刷新页面 | 新连接 + 新 ID → 登录 → 重新变绿 |

所以**重连之后必须再登录一次**：连接 ID 换了，光把右上角改成"在线"而不重新登录，
DM 那边就一直是灰点 —— 以前必须玩家手动刷新整个页面才会恢复。现在玩家端做了两件事：

1. `'connect'` 事件里只要已经登录过，就**静默重新登录**一次（不弹遮罩）；
2. 从后台切回前台（`visibilitychange`）或从 bfcache 恢复（`pageshow`）时，
   **主动换一条新连接**再走第 1 步 —— 因为浏览器把连接冻住过之后，服务端早就判我们离线了，
   而页面上看着还是"在线"。

配套的一条：**重连必须换新的订阅 ID**，不能交给 `EventSource` 的自动重连
（它会复用同一个 `?id=`）。复用的话，旧连接超时退出时的收尾
（注销这个 ID 的订阅 + 把该 ID 标记离线）会把刚建好的新连接一起带走，
表现就是"绿点闪一下就灰"。`realtime.js` 现在自己重连并每次换新 ID。

> 相关的回归断言已经进了 `smoke_test.ps1`：踢下线（= 连接断）之后，
> 用**新的连接 ID + 原令牌**重新登录，名册必须立刻回到 `online=true`。

## 5. 房间锁定

锁定后：新名字一律拒绝（`ROOM_LOCKED`），已有名字 + 正确令牌仍然可以重连。

## 7. 与 MAUI 版的关系

两个版本**共用同一套玩家端页面与 HTTP 接口**，玩家端无感。区别只在 DM 端怎么画：

| | MAUI 版 | 本版（Win7） |
|---|---|---|
| 运行时 | .NET 9 + Windows App SDK | .NET Framework 3.5 |
| 系统要求 | Windows 10 1809+ x64 | **Windows 7 SP1 及以上，32 位** |
| 安装要求 | 免安装（自包含，但目录约 255MB） | 免安装，**程序本体约 0.8MB**（不含自带素材） |
| DM 界面 | .NET MAUI（WinUI 3） | WinForms + GDI+（**控件全部自绘**） |
| 地图渲染 | MAUI Graphics | GDI+ 双缓冲 + 离屏位图 |
| WebView | 无（原生渲染） | 无（原生渲染） |
| 想要哪个 | 想要更现代的观感、且系统是 Win10+ → 日后会有安装程序 | 想一个 exe 通吃老机器、绿软双击即用 |

### 接口对照

接口路径、请求体、响应字段、HTTP 状态码**两版保持一致**：

> **⚠️ 第七轮起有一处例外**：绘图相关接口（`/api/terrain*`、`/api/drawing*`）和
> `map_change` 里的 `drawingVersion` **目前只有本版有**，MAUI 版还没同步。
> 两版玩家端的静态资源也暂时不再逐字节一致。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/player` | 玩家端页面 |
| GET | `/api/events?id=…` | SSE 实时推送 |
| GET | `/api/network` | 本机 IP / 端口 / 玩家地址 / 二维码 |
| GET | `/api/settings` | 网络面板完整状态（仅本机） |
| POST | `/api/settings` | 保存 IP / 端口并重开服务（仅本机） |
| GET | `/api/addresses` | 本机可用网卡地址列表（仅本机） |
| GET | `/api/maps` | 底图列表（含像素尺寸） |
| GET | `/api/maps/size/{name}` | 单张底图像素尺寸 |
| GET | `/api/maps/image/{name}` | 底图原图 |
| POST | `/api/maps/set` | 切换当前底图并广播（仅本机） |
| POST | `/api/maps/rotate` | 顺时针再转 delta 度（默认 90）并广播（仅本机） |
| POST | `/api/maps/gridcolor` | 设网格颜色模式 `auto`/`white`/`black`，返回解析后的实际颜色并广播（仅本机） |
| POST | `/api/maps/upload` | 上传底图，内容重复返回 409（仅本机） |
| POST | `/api/maps/remove` | **撤掉当前底图**（回到"只有网格"），文件保留（仅本机） |
| GET | `/api/terrain` | 绘图素材目录：三个分类 + 每张素材的名称/属性/不透明度 |
| GET | `/api/terrain/image/{kind}/{file}` | 素材原图（1254×1254，1.3–3.3MB），给电脑端列表缩略图用 |
| GET | `/api/terrain/tile/{kind}/{file}?px=64` | 缩到**一格大小**的贴图瓦片（`px` 夹在 16–512），手机端只拉这个 |
| GET | `/api/drawing` | 当前绘图内容 `{version, cells[]}`，数组顺序就是渲染顺序 |
| POST | `/api/drawing/clear` | 清空全部绘图并广播 `drawing_change`（仅本机） |
| POST | `/api/login` | 玩家登录 / 令牌校验 |
| GET | `/api/players` | 玩家名册 |
| POST | `/api/players/kick` | 踢人（仅本机） |
| POST | `/api/room/lock` | 房间锁定开关（仅本机） |
| POST | `/api/request_map` | 玩家拉取当前底图 |
| POST | `/api/ping` | 心跳 |

`仅本机` 的接口只接受来自 `127.0.0.1` 的请求，其余返回 403。
业务校验失败（如端口非法）统一返回 **HTTP 200 + `{"success":false,"message":"…"}`**，
调用方只看 `success` 字段，不靠状态码区分业务失败。

`map_change` 的载荷里除了底图信息，还带一个 `drawingVersion` 整数：

```json
{"image":"地板.png","url":"…","mode":"fill","rotation":0,
 "gridColor":"white","gridMode":"auto","drawingVersion":7}
```

手机端只在「这个版本号比自己手上的新」时才去拉 `/api/drawing`，所以平时不传绘图内容，
只传一个数字。这个字段必须同时出现在**广播的 `map_change`** 和 **`/api/request_map`
的单发响应**里 —— 两者共用同一个 `MapPayload`。少给后者的话，新加入的手机在 DM
再次落笔之前看不到任何已经画好的地形。

### 为什么用 SSE 而不用 SignalR / WebSocket

- 完全离线可用，不依赖任何需要额外部署的服务端组件。
- `TcpListener` 手写的 HTTP/1.1 服务器可以自由控制长连接，两个框架都能跑。
- 单向推送（DM → 玩家）足够覆盖全部场景，玩家 → DM 用普通 POST。
- `RealtimeHub` 用「队列 + 手动复位事件」实现，心跳在 15 秒一次，老机器毫无压力。

## 8. 性能设计（针对老机器）

| 问题 | 做法 |
|---|---|
| 每帧重缩放 3840×2160 大图 | **两级离屏缓存**：`_mapLayer` 先把底图重采样到控件尺寸（昂贵，只在底图/模式变化时做一次），`_scene` 再把 `_mapLayer` 与网格合成为画面（便宜，`OnPaint` 只做一次 `DrawImageUnscaled`）。拖网格滑块时只重建 `_scene`，**不再每格都重采样一次大图** |
| 成百上千条网格线逐条 `DrawLine` | 合并成一条 `GraphicsPath` 一次性描边，且只画视口内的线段 |
| 侧栏宽度动画时整棵树重排闪烁 | 侧栏自绘（`SidebarPanel`），动画只改自身宽度，控件树不动；地图控件不参与重排 |
| 面板滑入时逐帧改 Bounds | 面板位置一次算好，动画只改内容透明度与遮罩透明度 |
| 定时器频繁重建控件树 | 名册 / 网卡信息都直接读内存快照，用指纹比对，**变了才刷 UI**；轮询间隔放宽到 5s / 3s |
| 老机器 GC 抖动 | 不用 `async/await`、不用 `Task`，全部同步 + 定时器；绘图层尽量复用 `GraphicsPath`、`Pen`、`Brush` |

内存占用：

- 两级离屏位图各 = 窗口宽 × 高 × 4 字节（1920×1080 各约 8MB，共约 16MB）。
- 底图解码后约 = 像素数 × 4 字节（3840×2160 约 33MB），**同时只保留当前这一张**。
- 底图列表缩略图固定 80×80（约 25KB/张）。

结论：**DDR2 4GB 的 Win7 32 位机器跑得动。** 真正的瓶颈会是大底图的解码速度，
而不是运行时的持续开销。

### 9.4 完全离屏自检 `--selfcheck`（无人值守专用）

`--ui` 虽然能自动截图，但它**仍要开一个窗口**：无人在场时，Windows 可能弹出
"是否允许此未知发布者运行"的对话框，把整个流程卡死。为此程序另有一个**连窗口都不建**的模式：

```bat
bin\Release\TrpgMaps.exe --selfcheck build_logs\selfcheck
:: 或走编译脚本（编译 + 自检一并做）
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -SelfCheck
```

它**不开窗口、不启动 HTTP 服务、不生成任何对话框**，只做这几件事：

1. 用 `Graphics.FromImage` 在内存里画 6 张场景图，覆盖"无底图 / 有底图(fill) / 有底图(contain)"
   × "2.5cm / 3.0cm / 1.0cm" 的组合，写到 `01-grid-only-2.5cm.png` … `06-grid-only-1.0cm.png`；
2. 对每一张**断言** `格子像素 = cm × 37.8`，并打印"有底图时格子是否变化"的对照表；
3. 另起一张**四象限彩图**（左上红 / 右上绿 / 左下蓝 / 右下黄）当探针，
   把底图分别顺时针转 0°/90°/180°/270° 渲染一遍，再从位图上**把四个角的像素读回来**
   判断颜色 —— 红块出现在右上角才说明"转的是顺时针 90°"。
   走的是完整链路（`new MapCanvas` → `SetMap` → `SetRotation` → `RenderScene` → 读像素），
   不是去看某个内部字段有没有被赋值；
4. 打印侧栏在收起(60px)/展开(180px)下的按钮边距与图标位置几何；再断言**最底部那颗
   「关于」按钮真的贴在底边**（底边距必须等于 `TopPadding`=12、且不与上方按钮重叠）——
   它是从底边往上数的，不跟着上面那一列走；屏幕截图在非 100% DPI 下右下角会被裁掉
   （见 9.2），"在最边上"的东西恰恰是截图最容易骗人的地方，所以只认数字；
5. **网格颜色判定**：临时造两张纯色探针 —— 亮底图（240,236,224，均值 0.91）和
   暗底图（30,30,34，均值 0.12）—— 断言 `auto` 分别给出黑线 / 白线；再对同一张图
   连测两次，断言第二次走的是缓存（`FromCache=true`）；
6. **网格线在像素上到底看不看得见**：把「黑线×亮底图 / 白线×亮底图 / 白线×暗底图 /
   黑线×暗底图」四种组合各渲染一遍，在某个格子**正中间**那一行（避开网格线本身）上取样，
   以**该行亮度的中位数**当底色（网格线只占 1200 像素里的十来个，中位数必然是底色），
   再数偏离中位数超过 **0.10** 的像素个数：应该看得见的必须数得出来，应该看不见的必须为 0。
   四张场景图存成 `_grid_*.png`；
7. 顺手把 `maps\` 里每张底图的平均亮度列成一张表（只报告，不断言），
   这样"某张图为什么被判成白线"可以直接对着数字看；
8. **绘图几何 / 图层 / 渲染**（`--- drawing: snap / distance / shapes ---`）四段：
   先断言半格吸附、距离换算、四种形状的覆盖格数，**以及严格 / 宽泛两种选区方式的格数**
   （球形 r=4：13/21、球形 r=3（圆与格线相切）：9/9、立方 r=4：25/25、
   立方 r=3（正方形边线压在格线上）：9/9、锥形 90°：5/7 且宽泛不向后溢出，
   另外两条是专盯"相切不算"的：r=3 时轴向第 2 格、90° 扇形的上/下两格，
   都在宽泛里必须**不在**；
   再加一条「宽泛 ⊇ 严格」和一条「线形两种方式同解」—— 宽泛那套判定要是漏掉一整类格，
   红色反而会比严格少，这条断言就是抓这个的）；
   再断言"地形一格一层、物品一格一层、实体不限层数、快照顺序地形在前、橡皮只擦掉指定格、
   清空实体后地形保留、存盘读回顺序一致"；
   接着断言**按素材清空**：面板上「清空本类」（行为=按素材）只摘掉点名的那一张素材，
   同类里别的素材与别的分类一格不动，报一个不存在的文件名或空文件名必须是**纯粹的空操作**
   （不能退化成"清空整类"）；
   最后**真的画一格**（挑素材列表第一张），从像素上回读
   "贴图落在指定格、相邻格干净、同一张图在两格里的左内缩量一致（±2px）"，
   再摆一个选区断言"半透明红能透出底色、选区外没被染色、候选落点可见、距离读数方块可见"；
9. **笔刷"实际形状"层**（`--- drawing: brush shape outline (blue) ---`）六条，
   全部靠**沿射线扫最外圈的偏蓝像素**再比距离（详见下面那一节）：
   - 蓝圆在 0°/90°/180°/270°/45° 五个方向量到的半径必须一致（±6px）
     —— 这一条专门区分"真圆"和"方框包围盒"：方框在 45° 上会偏出 √2 倍（≈195px）；
   - 蓝方块的轴向上是半径、对角上必须是 √2 倍（两侧都要对上，说明它真的是方块而不是圆）；
   - 蓝扇形在张角内量到半径、张角外一条蓝色像素都没有（50° 那条射线要**跳过顶角 80px**
     再开始扫，否则会扫到顶角两根描边抗锯齿糊成的那一小团）；
   - 重叠区红蓝两层都看得见（`R-G>15` 且 `B-G>15`：纯红层 `B==G`、纯蓝层 `R` 低，
     只有两层都画上去才会两头抬起来）；
   - **蓝色伸进未选中格的那一角必须"只有蓝、没有红"** —— 这是加这一层的原因本身，
     同时也反证"红色覆盖格的判定没有被改"；
   - 蓝线段画在中点、线外一格是干净底色（采样点要挑**格心**，别落在网格线上）。
10. **WebP 解码**（`--- webp (self-hosted VP8 decoder) ---`）：把 `maps\` 里每一张 `.webp`
   用自研解码器解一遍，断言三件事 ——
   **① 解码尺寸必须等于「只读文件头」量到的尺寸**（这条抓的是"图能画出来但格数算错"那类静默故障）；
   **② 亮度标准差 ≥ 0.02、不同亮度级数 ≥ 24**（不是一片糊 / 不是纯色）；
   **③ 不是全黑也不是全白**。同时打印每张的解码耗时，并把第一张导出成 `_webp_decode.png`
   供目视，另外导出 `_webp_y/u/v.raw` 三个平面原始数据，方便跟 libwebp 逐像素对拍。

## 10. 已知差异 / 简化

- **只支持 Windows。** 这一版的目的就是老 Windows 机器，不追求跨平台。
- **不改系统代理、不做 HTTPS。** 局域网内明文 HTTP，和原版一致。
- **二维码纠错级固定为 M，版本 1–10。** 玩家地址长度有限，够用；超出会报错。
- **重启服务只重启 Kestrel 的等价物（`TcpListener`）**，底图 / 名册 / 令牌都在内存里保留，
  所以改 IP / 端口不需要重开程序（已由 `auth_test.ps1` 覆盖验证）。
- **界面字体固定微软雅黑。** Win7 自带；若被精简掉了会退回到系统默认字体，不影响功能。
- **WebP 只支持 lossy `VP8 ` 关键帧**（`maps\` 里那 19 张全是这种）。
  - 无损 WebP（`VP8L`）和带透明通道的 WebP（`VP8X` + `ALPH`）**会明确报错**，
    错误信息直接告诉你怎么转（例如 `cwebp -q 90` 走有损）—— 不是"静默画个黑图"。
  - 不带 alpha 的 `VP8X` 容器（里面装的还是 `VP8 `）能正常解 —— `FindVp8Chunk` 是扫全部 RIFF 块找
    `VP8 ` 的，不要求它一定在第一块。

## 11. 数字签名与"未知发布者"弹窗

把 exe 发给别人、或从网上下载后再运行时，Windows 会弹"未知发布者 / 是否允许运行"，
看着不正式。**完整说明见根目录 `签名说明.md`**，要点：

- **自己签（自签名证书）** —— 本机免费，用 `tools\sign-release.ps1` 一键给三个 exe 签名；
  但**只在装了这张证书的机器上有效**，别人拿到仍会告警。
  本机要让自己不再告警，需运行一次 `-TrustCert`（会弹一次 UAC / 证书确认，**只点这一次**）：

  ```bat
  powershell -ExecutionPolicy Bypass -File tools\sign-release.ps1 -TrustCert
  ```
- **给别人用** —— 要买 **OV / IV 代码签名证书**（约 $80–400/年，私钥必须在硬件令牌/HSM 上），
  或用 **Microsoft Store 的 MSIX**（免费、零告警）。
  注意：**EV 证书从 2024 年起已不再能立刻跳过 SmartScreen**，别被中介忽悠。
- **无人值守时怎么不被弹窗打断** —— 两招：
  1. 跑 **`--selfcheck`**（第 9.4 节）：完全不开窗口，根本不会触发那个对话框；
  2. 跑 `--ui` 时带上 **`--no-server`**（`--ui` 已自动隐含）：不监听端口，就不会弹防火墙授权。

  另外，那个"是否允许运行未知程序"的对话框只针对**带 Mark-of-the-Web 的文件**（浏览器/邮件下来的）。
  从 U 盘、局域网共享直接拷过去的文件通常不带 MOTW，不会被拦。
- **防火墙弹窗和签名无关**：程序第一次监听局域网端口时 Windows 会问"是否允许联网"，
  这是**每个程序只弹一次**的防火墙规则确认，签不签名都一样。

  > ⚠️ **这个框一定要点「允许访问」，别关掉。** 关掉不会"什么都不做"，而是写一条永久阻止规则，
  > 之后手机永远连不上、系统也再也不问。完整原理与修复见 **第 13 节**。
  >
  > 现在程序自己会处理：启动时主动查状态、被挡住就提示并提供一键放行，
  > 首次启动还会临时取消置顶让这个框露出来。也可以直接双击 **`放行防火墙.bat`**。

## 12. 当前签名状态

本机已生成一张自签名开发证书（`CN=TrpgMaps Local Build (self-signed, dev only)`），
并给两个产物都打上了签名：

| 产物 | 摘要算法 |
|---|---|
| `maui版本\...\win-x64\TrpgMaps.exe` | SHA-256（MAUI 只跑 Win10 1809+，SHA-256 没问题） |
| `win7版本\bin\Release\TrpgMaps.exe` | **SHA-1**（兼容未打补丁的裸 Win7） |

>
> ```powershell
> $isNet35 = ($file -notlike '*net9.0-windows*')   # 不在 MAUI 输出目录里 = Win7 版 -> SHA-1
> ```
>
> 这样以后再怎么改文件名都不会签错算法。

> 签名信息里显示 `UnknownError`（= 证书不在受信任根里）是**预期的**，
> 直到在本机跑过一次 `sign-release.ps1 -TrustCert` 才会变成 `Valid`。
> 重新编译会覆盖 exe、签名随之丢失，需要重新跑一次签名脚本（脚本会自动复用已有证书，不会重复建证书）。

## 13. 手机打不开玩家页面？先看防火墙

这是本版**踩过的最隐蔽的一个坑**，单独写一节。

### 症状

- DM 端看起来**一切正常**：服务起来了、`玩家地址` 和二维码都对、手机扫得出地址；
- 但手机（平板）浏览器打开那个地址**一直转圈、最后超时**；
- **同一台机器上 MAUI 版完全正常** —— 于是很容易误判成"网络问题 / 手机问题 / 路由器 AP 隔离"；
- 本工程**所有自测全部通过**（当时 smoke 33/33、auth 35/35、截图 7/7）。

### 根因

Windows 防火墙为**每个程序**单独记入站规则。某个程序第一次监听端口时，
系统弹一次"是否允许此应用通过防火墙通信"：

| 你的选择 | Windows 实际做了什么 |
|---|---|
| 允许访问 | 写一条**入站允许**规则（`Defer=User`），以后不再问 |
| **取消 / 按 Esc 关掉** | 写一条**入站阻止**规则，**而且以后再也不问** |

本程序默认是**全屏无边框 + 置顶**的（给 DM 投屏用），而那个授权框是个**普通窗口** ——
它会被压在全屏界面底下，**用户既看不见也点不到**。随手一按就变成了第二种情况：
一条永久的入站阻止规则写进系统，之后无论重启多少次都不会再提示。

**而防火墙的判定顺序是"阻止优先于允许"**，所以哪怕别的程序（比如 MAUI 版）已经拿到放行、
哪怕有 5000-5020 的端口放行规则，只要这一条针对本 exe 的阻止规则还在，手机就永远连不上。

### 为什么自测发现不了

接口测试全部走 `http://127.0.0.1:5000`，而**Windows 防火墙不过滤回环流量** ——
所以（当时）33 项检查全部通过，手机却一个都连不上。这个盲区已经补上：
`smoke_test.ps1` 现在会直接读防火墙规则表并断言"不存在针对本程序的入站阻止规则"。

### 怎么修

**三种方式，任选一种**（都要一次管理员确认，这是 Windows 的硬性要求，绕不过去）：

1. 双击 **`放行防火墙.bat`**；或
2. 命令行：`bin\Release\TrpgMaps.exe --fix-firewall`；或
3. 界面 → 侧栏「网络」→ 点 **「放行防火墙（需管理员确认）」**。

三种走的都是同一段代码，做四件事：

```
netsh advfirewall firewall delete rule name="TrpgMaps"
netsh advfirewall firewall delete rule name=all dir=in program="<本程序完整路径>"
netsh advfirewall firewall add rule name="TrpgMaps" dir=in action=allow ^
      program="<本程序完整路径>" enable=yes profile=private,public protocol=TCP
（再同样加一条 UDP）
```

- 先**按名字**删：Windows 自动写下的规则都叫 `TrpgMaps`，
  这样能连"以前在别的目录跑过"留下的僵尸阻止规则一起清掉。
- 再**按程序路径**兜一遍，防止有别的名字的规则压着。
- 放行同时给 `private` 和 `public`：家里 WiFi 被标成"公用网络"的情况太常见了。
- 改完会**再读一次规则表复查**，只有确认变成"已放行"才返回成功。

### 平时怎么避免撞上

- 首次启动那几秒，程序会**临时把置顶关掉 8 秒**，让系统那个授权框有机会露出来 ——
  看到它请点「允许访问」。
- 启动时程序会**主动查一次**状态（读注册表，不需要管理员权限）。
  如果发现已经被阻止，会直接弹窗告诉你原因并问要不要放行 —— 不用你自己去猜。
- 网络面板里那一行 `防火墙：…` 随时反映当前状态。

### ⚠️ 改 exe 名字 = 把这条坑重新踩一遍

**Windows 那条自动写下的入站规则是绑在"程序完整路径"上的，不是绑在端口上。**
所以**只要 exe 的名字（或所在目录）变了，旧规则就管不到新文件了**：

| 时间点 | 现象 |
|---|---|
| 改名之前 | `放行防火墙.bat` 已经跑过，状态是 `allowed`，手机连得好好的 |
| **改名的第一天** | `smoke_test.ps1` 的防火墙那条**突然 FAIL**：`state=blocked allow=0 block=2` |
| 真相 | 不是网络出问题，也不是改代码改坏了 —— 是 Windows 为**旧路径**写了阻止规则，对新路径重新弹了一次框（多半又被全屏界面压住、又被 Esc 关掉了） |

> **怎么快速确认不是别的问题**：本机网卡、玩家地址、静态资源、二维码这四条同时还是
> `[PASS]`，只有防火墙那条 FAIL —— 就说明**服务本身完全正常**，纯粹是规则表的事。
> （回环流量不过防火墙，所以自测的 HTTP 全部照常通过，这个 FAIL 是唯一能看见问题的窗口。）

**修法还是那三个入口之一**，不用管路径变过几次 ——
`Repair()` 里除了按名字删，还有一条**按程序路径删**，所以新旧路径的僵尸规则会被一起清掉：

```bat
放行防火墙.bat        :: 或 bin\Release\TrpgMaps.exe --fix-firewall
```

修完再跑一次 `smoke_test.ps1`，那一条会回到 `state=allowed allow=2 block=0`。

> 顺带一提：MAUI 版和 Win7 版是**两个不同的 exe 路径**，所以**两版要各自放行一次**，
> 互不代替。这也是为什么两版的 `smoke_test.ps1` 里都有这条检查。

### 相关文件

| 文件 | 作用 |
|---|---|
| `Core/FirewallCheck.cs` | 查（读注册表规则表）+ 修（netsh）都在这 |
| `放行防火墙.bat` | 双击入口 |
| `--fix-firewall` / `--quiet` | 命令行入口 |
| `smoke_test.ps1` 的「firewall: can a phone actually reach us?」 | 回归守卫：被阻止就直接判 FAIL |

## 14. 安装包、便携包与升级包

一条命令出全套：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\make_release.ps1
```

它会：编译三个工程 → 打内嵌负载 → 打三个发布包 → 跑一遍功能自检 →
写 `version.json` → 打源码 zip。**全程不需要管理员、不开窗口**，可以无人值守跑。

### 14.1 三类产物的区别

| 产物 | 给谁 | 装完长什么样 |
|---|---|---|
| `..._installer.exe` | 想要快捷方式 / 能在"设置 → 应用"里卸载的人 | 装进 Program Files、写注册表、建快捷方式、放一个卸载程序 |
| `..._portable.zip` | 想放 U 盘 / 换机器就拷的人 | 解压即用，不碰系统任何地方 |
| `..._update.zip` | 已经装了任意一版、只想升级的人 | 只覆盖程序文件（约 1 MB），大素材不带 |

前两个是**同一份负载**（`installer/payload.zip` 和 portable 包内容完全一样），
差别只在"要不要把卸载信息写进系统"。

负载是**允许清单**：`TrpgMaps.exe` / `TrpgMaps.exe.config` / `Resources` / `wwwroot` / `maps` /
`terrain` / `entity` / `item` / **`放行防火墙.bat`**。用允许清单而不是排除清单，
是为了"开发者不小心丢进 `bin\Release` 的新文件"不会自己溜进发布包。

> `放行防火墙.bat` 是**源码文件不是编译产物**，所以由 `make_release.ps1` 从工程根目录单独拷进负载；
> 而它的文件名是中文、脚本又必须纯 ASCII，所以文件名是**用码点拼**出来的
> （`[char]0x653E`…`[char]0x5899`）。脚本里为此加了断言，确认它真的在 portable 与 update 包里
> —— 否则用户会按 Readme 去双击一个根本不存在的文件。
> 该 .bat 同时兼容两种布局：先找 `%~dp0TrpgMaps.exe`（发布出来的目录），
> 找不到再退 `%~dp0bin\Release\TrpgMaps.exe`（开发目录）。

### 14.2 为什么安装包和升级器都是自己写的 C#

本工程是"零第三方运行期 DLL + 单 exe 绿色部署"路线（见第 2 节），
引入 Inno Setup / NSIS 就等于给发布流程加一个外部工具依赖，而且它们生成的卸载器
是另一个 exe，风格、编码、报错方式全都不一样。自己写两个小工程反而更省事：

- **安装器**（`installer/`，约 34 MB —— 大头是内嵌的负载）：WinForms，v3.5，
  `app.manifest` 里 `requireAdministrator`。**单文件**：负载作为嵌入资源
  （逻辑名 `TrpgMaps.payload.zip`）打进去，发布时只给用户一个 exe。
- **升级器**（`updater/`，几十 KB）：只链四个 Core 文件，不含任何界面代码。

两个工程都用 `<Compile Include="..\Core\X.cs"><Link>` 复用了主程序的源码，
所以**注册表格式、快捷方式做法、ZIP 解包只有一份实现**，不会三处跑偏。

### 14.3 卸载项写在哪儿（`Core\AppRegistry.cs`）

| 注册表位置 | 干什么 |
|---|---|
| `HKLM\SOFTWARE\...\CurrentVersion\Uninstall\TrpgMaps` | **控制面板 / "设置 → 应用"里那一条**就靠它；也是"安装版"身份的唯一判据 |
| `HKLM\SOFTWARE\TrpgMaps` | 安装时勾了哪些快捷方式；卸载和"修复注册信息"回来读它 |
| `HKCU\SOFTWARE\TrpgMaps\Update` | "不再提示此版本"（写 HKLM 要管理员，而这是个随手动作） |

⚠️ 本程序是 **32 位**的，所以在 64 位系统上访问 `HKLM\SOFTWARE\...` 会被 WOW64
**自动重定向到 `Wow6432Node`**。这不是 bug —— 32 位程序的安装记录本来就该写在那儿，
控制面板两边都会读。**安装器、主程序、卸载器三者位数一致**，读到的永远是同一份；
不要为了"看得见"去手工写非重定向的路径。

### 14.4 两个踩过的坑

**① 装到 Program Files 之后程序写不了自己的目录。**
本程序是绿色部署：底图上传、`drawing.json`、`app.log` **全都写在 exe 自己的目录里**
（见 `AppEnv`）。而 Program Files 默认只读，装完就会"能打开、上传失败、画的东西存不下来"。

安装器因此在解包之后跑一次 `icacls <目录> /grant *S-1-5-32-545:(OI)(CI)M /T /C /Q`：
- 只给 **`BUILTIN\Users`**，不给 Everyone；
- 用 **SID 而不是组名**：`Users` 这个组名在非中英文系统上会被本地化（德语是 `Benutzer`），
  写名字会直接失败；
- 这是"绿色部署"换来的一致性代价：便携版和安装版的写盘行为完全一样。
  真要改掉，得把运行期数据挪到 `%LOCALAPPDATA%`，那是一次不小的重构。

**② 批处理里的中文路径。**
`cmd.exe` 按**当前代码页**解释 `.bat` 的字节，安装目录一旦有中文
（`C:\Program Files (x86)\TrpgMaps` 没问题，用户自定义目录就不好说了），
批处理里的字面量路径就可能变成问号。所以本工程里**批处理一律不写字面量路径**：

- 升级包里的 `delete.bat` / `fix-registry.bat` 只做转交：
  `"%~dp0TrpgMapsUpdater.exe" --delete-only "%~dp0" "%~1"`，
  路径靠**参数**传进去（`CreateProcessW` 走的是 Unicode，不经代码页），
  要删的文件清单则放在 UTF-8 的 `update.json` 里由托管代码读。
- 卸载器的自删除脚本（`SetupEngine.ScheduleSelfDelete`）同样只引用 `%~1` / `%~2`。

### 14.5 升级是怎么走完的

```
主程序                          升级器（新进程）                     系统
  │ 下载 update.zip                  │
  │ 解到 %TEMP%\TrpgMaps_update_*    │
  │ ─── 启动 TrpgMapsUpdater.exe ──▶ │
  │ 退出                             │ 等 TrpgMaps.exe 退出
                                     │ 覆盖 payload\**
                                     │ 按 update.json 删 deleteFiles
                                     │ 安装版？→ runas 自己 --register-only
                                     │           （写注册表 + 重建快捷方式）
                                     │ 重启主程序
```

**为什么必须另起一个进程**：正在运行的 exe 换不掉自己（Windows 锁住映像文件）。
主程序启动升级器之后**必须真的退出**，这也是 `BeginUpdate()` 最后那句 `Close()` 的原因。

**便携版 vs 安装版怎么判**：`AppRegistry.IsInstalledAt(AppEnv.Root)` ——
不只是"注册表里有没有记录"，还要**比对目录**。只看记录是不够的：
用户完全可能把安装目录整个拷到 U 盘上跑，那种情况必须按便携版处理
（只覆盖文件 + 执行删除），否则会去改一堆指向不存在目录的键。

**升级器自己提权、程序本体不提权**：只有"写 HKLM + 建所有用户快捷方式"那一步需要管理员，
所以升级器先以普通权限覆盖文件，再 `runas` 把自己拉起来只做注册表那一步。
这样主程序永远不会以管理员身份运行（以管理员跑的话，拖到窗口上的文件会变成"管理员所有"）。

### 14.6 `update.json` 与 `version.json` 不是一回事

| 文件 | 说的是 | 在哪 |
|---|---|---|
| `version.json` | **仓库**里有什么版本（远端 vs 本机） | 仓库的 `win32\` 里，程序主动去拉 |
| `update.json` | **这个包里**装了什么（覆盖谁、删谁） | 升级包内部 |

字段不重叠，故意分成两个类型（`UpdateManifest` / `UpdateManifestFile`），混着用容易看错。

`update.json` 的 `deleteFiles` 里现在列的是**19 张早期版本随包发布的 PNG 底图**：
它们后来被体积只有 1/20 的 `.webp` 取代，老版本升上来之后那些 PNG 会白占 50 MB。
清单**只列这些确切文件名**，用户自己上传的图片一张都不会动。
这份清单在 `make_release.ps1` 里是**从 `maps\` 目录现推的**（`X.webp` → `maps/X.png`），
不是硬编码 —— 两头对不上时能自己发现。

### 14.7 发布前自检（`make_release.ps1` 第 5 步里那段）

真实的"装到 Program Files"需要 UAC，无人值守跑不了。所以脚本改为**在它下面一层做实打实的验证**，
全部通过才允许出包（任何一条 FAIL 就是 `exit 1`）：

| 检查 | 挡住什么 |
|---|---|
| 三个包都能被**我们自己的** ZIP 读取器解开（`--test-zip`） | 只有到用户机器上才炸的包格式问题 |
| 条目名里没有反斜杠、中文名按 UTF-8 正确往返 | 打包工具写错分隔符 / 编码 |
| 安装器 exe 里确实嵌了 `TrpgMaps.payload.zip`，且体积 ≥ 负载 | `LogicalName` 写错 → 装出来是个空壳 |
| `放行防火墙.bat` 确实在 portable 与 update 包里（按 UTF-8 名字做字节搜索） | 漏拷 → 用户按 Readme 去双击一个不存在的文件 |
| `delete.bat` 路径：列出的 19 个文件**全被删掉**、用户上传的图片**没被动**、没列的文件**没被动** | 删除清单写错 → 删掉用户的地图 |
| `--apply` 路径：payload 落到目标目录、`TrpgMapsUpdater.exe` 自己**不会**被拷进安装目录、用户数据仍在 | 覆盖范围写错 |

另外还有两个**需要管理员**的入口，只能人工跑：

```powershell
TrpgMapsSetup.exe /selftest D:\temp\selftest   # 把内嵌负载解出来核对（其实不需要管理员，但 manifest 要求提权）
TrpgMapsSetup.exe /uninstall                   # 卸载向导
```

> `SetupEngine.ScheduleSelfDelete` 生成的清理批处理里**一个中文字面量都没有**
> （路径全靠参数传），所以在中文 Windows 上不会因为代码页出问题。

### 14.8 出包时的命名与版本号

文件名统一 `TrpgMaps_v<版本>_win32_<installer|portable|update>`，
由 `AppInfo.ReleasePrefix` 拼出来，`make_release.ps1` 从 `Core\AppInfo.cs` 里读版本号
（**不是**从 `AssemblyInfo.cs` 读，也不是自己写一份）。

**改版本号要动两处**：`Core\AppInfo.cs` 的 `AppInfo.Version` 和
`Properties\AssemblyInfo.cs` 的 `AssemblyVersion`/`AssemblyFileVersion`，
以及 `installer/`、`updater/` 各自的 `AssemblyInfo.cs`。
懒办法是搜一遍 `1.0.0`。

源码 zip（`TrpgMaps_v<版本>_win32_src.zip`，放在工作区根目录）是**给 GitHub / Gitee 的仓库内容**：
解出来就是"仓库根"，布局固定成三样 ——

```
Readme.md      面向使用者的说明（最低配置 + 使用方法），外层唯一给用户读的文件
.gitignore     外层忽略规则（工作区根目录那份，由脚本拷进包）
win32\         工程本体 = 本机 win7版本\ 的内容
```

**本机目录名和发布目录名是故意不一致的**：本地一直叫 `win7版本`，只有上传的这个副本改名成
`win32` —— 因为 `AppInfo.RepoDir` 和更新 URL 都写死了 `win32`，仓库里的目录名必须跟着对上
（脚本打包时把工程目录拷成 `win32\`；改名要连着 `Core\UpdateCheck.cs` 的候选地址一起想）。

外层 `.gitignore` 与 `win32\.gitignore` **分两层、不能合并**：git 的忽略模式只要含斜杠
（如 `installer/payload.zip`）就是相对该 `.gitignore` 所在目录锚定的，写在外层匹配不到。
另外注意 `README.md`（本文件，开发文档）与 `Readme.md`（使用者说明）**Windows 视为同一个名字**，
所以它们现在分别待在 `win32\` 与外层，正好不会再互相覆盖。

`版本说明.md`、`开发须知.md`、`签名说明.md` 都不进那个 zip。
